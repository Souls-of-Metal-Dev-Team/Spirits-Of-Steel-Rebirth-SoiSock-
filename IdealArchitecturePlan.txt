     │                                                                         │
     │ docs/Excalidraw/IdealArchitectureDiagram.excalidraw.md describes a      │

     │ real multiplayer as the end goal.                                       │
     │                                                                         │
     │ Diagram, decoded:                                                       │
     │ - ServerSide: GameState is the single hub. Three manager groups read it │
     │   (GetState) and write it (SetState):                                   │
     │   - "MapManager" group: Faction, Country and Province managers. They    │
     │     chain Action/Reaction calls (Faction to Country to Province, and    │
     │     Reaction back up).                                                  │
     │   - "InterpreterManager" group: Decision, Plans and Figure managers,    │
     │     which talk to each other in both directions.                        │
     │   - "Operate On Province" group: Resource, Building and Troop managers. │
     │     They "Add Things To Provinces".                                     │
     │   - StateLoader reads Scenarios or Saves and does SetState on           │
     │     GameState.                                                          │
     │ - ClientSide: PlayerController1, PlayerController2, AIControllers and   │
     │   Debug/Admin Controller send Actions to GameState. Each human          │
     │   controller gets input from its own "UI + Sound + keyboard shortcuts"  │
     │   box.                                                                  │
     │                                                                         │
     │ Current code, compared:                                                 │
     │ - No single state hub. State is spread over the autoloads. GameState.cs │
     │   holds only UI/session flags (interactionType, game_ui, tooltip,       │
     │   decision_menu_open).                                                  │
     │ - Managers form a full mesh. For example, WarManager references 6 other │
     │   managers, and MapManager references 5.                                │
     │ - MapManager.cs (2191 lines) mixes 4 jobs: data loading, rendering      │
     │   (colors, map modes, hover), input (SelectCountryAt, DeployAt,         │
     │   BuildAt), and simulation (TransferOwnership, AnnexCountry,            │
     │   OccupyProvince).                                                      │
     │ - No action layer. UI and AI call mutators directly. Examples: GameUI   │
     │   calls MapManager.AnnexCountry and WarManager.call_to_arms.            │
     │   TroopSelection calls TroopManager._create_new_split_troop and         │
     │   RemoveTroop. CountryAI calls WarManager.declare_war,                  │
     │   TroopManager.command_move_assigned and                                │
     │   MapManager._ProvinceBuildIndustry.                                    │
     │ - The code assumes one player: CountryManager.player_country has 49     │
     │   references.                                                           │
     │ - Managers from the diagram that do not exist yet: Province, Building,  │
     │   Resource and Figure managers, and StateLoader. Their logic is now     │
     │   inside MapManager, EconomyManager and World.                          │
     │ - Already close to the diagram: Decision, Plans, Interpreter and        │
     │   Faction managers, and CountryAI (it is already a separate controller  │
     │   class).                                                               │
     │                                                                         │
     │ Multiplayer blockers (beyond the diagram):                              │
     │ - TroopManager._Process and WarManager._Process advance the simulation  │
     │   on frame delta * time_scale, and battles use Timer nodes. Two clients │
     │   will not stay in sync.                                                │
     │ - There are 55 RNG call sites (GD.Randf and similar) with no shared     │
     │   seed.                                                                 │
     │ - Simulation data holds Godot resources. For example, TroopData holds a │
     │   Texture2D flag.                                                       │
